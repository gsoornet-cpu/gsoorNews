01

الملخص التنفيذي

جسور مشروعان متداخلان لا مشروع واحد: واجهة تجريبية ثابتة، ومواصفات كاملة تصف منصة استخباراتية-إخبارية معقدة.

الديمو — نحو 26,000 سطر HTML/CSS/JS بلا أي خادم حقيقي، يعمل بالكامل على بيانات وهمية في data.js لا تُحفَظ بعد إعادة التحميل. ممتاز كمرجع تصميم وتجربة استخدام، لكنه صفر بالمئة من البنية التقنية الحقيقية.

المواصفات (32 قسمًا) تصف خط أنابيب ذكاء اصطناعي من 22 مرحلة، نظام حالات آمن «اطمّن» بتشفير حقلي، ذكاء جغرافي مُجمَّع بقاعدة k-anonymity، غرفة أخبار بعشرة أدوار RBAC، وبنية .NET / PostgreSQL+pgvector / Redis / Elasticsearch / Azure كاملة.

الحقيقة الهندسية الجوهرية

لا يوجد سطر واحد من الديمو قابل لإعادة الاستخدام مباشرة في الخلفية. القيمة الحقيقية: نظام تصميم متكامل، هيكلة صفحات مُختبرة مع العميل، وتدفقات تفاعل يمكن أن تُبنى عليها الواجهة النهائية — لا كودها.

المشروع الكامل مشروع 6–10 أشهر بفريق من 4–6 مهندسين، وتعقيده الحقيقي في خط أنابيب الذكاء الاصطناعي، وخصوصية/أمان اطمّن، وكشف التكرار الدلالي — لا في عدد الصفحات.

ما يستحق الحفاظ عليه

نظام التصميم الكامل (ألوان، تايبوغرافيا RTL، بطاقات). هيكلة الصفحة الرئيسية: عاجل ← قصة رئيسية ← خط أحمر ← اللمة الحلوة ← رياضة ← الجيل الثاني. شكل تجربة وضع الأزمة. هيكل شاشات CMS قريب فعليًا من أدوار المواصفات.

ما هو Throwaway بالكامل

كل كود JavaScript الوظيفي — لا بنية مكوّنات (لا React/Next.js)، لا فصل بين العرض والبيانات، ومنطق الأمان (auth, OTP, صلاحيات) غير مُصمَّم أصلًا، لا "ناقص" فقط.

مراحل التطوير

مبنية على تبعيات هندسية فعلية — كل مرحلة تُنتج نظامًا يعمل، لا كودًا جزئيًا.

Phase 0 — الأساس التقني

3 أسابيع

إعداد Repo، PostgreSQL + Migrations أولى، ASP.NET Identity + JWT، Key Vault، CI/CD أساسي، Next.js Scaffold. DoD: مطوّر جديد يُشغّل النظام محليًا خلال أقل من ساعة.

Phase 1 — خط الأخبار + محرك الملاءمة

4 أسابيع

Worker لكل طبقة مصدر (1–3)، خط أنابيب مبسّط، تصنيف ملاءمة Embeddings+Rules، أول استدعاء LLM للحالات الحدّية. Deliverable: مقالات حقيقية على الصفحة الرئيسية.

Phase 2 — الدول/المدن + اطمّن الكامل

5 أسابيع

هرمية جغرافية كاملة، Case مشفّر حقليًا، OTP فعلي، توزيع يدوي على فريق استجابة، حالة حيّة عبر SignalR. أعلى أولوية أمنية في المشروع بأكمله.

Phase 3 — غرفة الأخبار الأساسية

4 أسابيع

RBAC لعشرة أدوار، طابور مراجعة بشرية إلزامي، محرر مقال، نشر فعلي، Schema.org + Sitemap أساسي. نهاية MVP ≈ 14–16 أسبوعًا.

Phase 4 (V1) — الأتمتة والذكاء الجغرافي

10–12 أسبوعًا

كشف تكرار كامل، وضع أزمات تلقائي، تنبيهات جغرافية، شبكة مساهمين، قسم الرياضيين.

Phase 5 (V2) — الاستخبارات الاستراتيجية

12–14 أسبوعًا

خريطة مهجر مُجمَّعة، خريطة معرفة، بحث دلالي متقدم، تصعيد أزمات متعدد المستويات.

التوازي الممكن

Next.js scaffold يبدأ من اليوم الأول بالتوازي مع Phase 0 عبر mock API مؤقت (عقد الديمو تقريبًا) يُستبدَل لاحقًا بـ API حقيقي. DevOps يُعِد IaC بالتوازي مع Phase 1. تصميم شاشات CMS يبدأ بالتوازي اعتمادًا على تخطيط الديمو الحالي.

المسار الحرج

  1. Phase 0 — Auth + DB + CI/CDيحجب كل شيء لاحقًا. أي تأخير هنا ينزلق بالكامل على المشروع.
  2. نموذج Case المشفّر + OTPأعلى مخاطرة أمنية؛ لا يمكن إطلاق MVP بدونه مهما اكتملت بقية الميزات.
  3. محرك الملاءمةإذا كان ضعيفًا، كل المحتوى اللاحق منخفض الجودة تحريريًا — يستحق وقتًا إضافيًا حتى لو أخّر الجدول.
  4. كشف التكرار (V1)يعتمد على حجم بيانات حقيقي من MVP لضبط العتبات — مخاطرة جدولة حقيقية، لا مجرد تنفيذ.

عناصر مستقلة قابلة للتوازي: تصميم شاشات CMS، قسم الرياضيين (V1)، السيو الأساسي، الفيديو هاب.

التوصية النهائية

  1. مدى التعقيد الحقيقي؟عالٍ — بسبب اطمّن (بيانات حساسة) وخط أنابيب AI وكشف التكرار الدلالي، لا عدد الصفحات. منصة استخبارات معلوماتية، لا موقع أخبار.
  2. المدة الواقعية؟≈ 36–42 أسبوعًا حتى V2 بفريق 6 أشخاص متوازٍ جيدًا؛ MVP وحده ≈ 14–16 أسبوعًا.
  3. ما يُبنى أولًا؟محرك الملاءمة + اطمّن بخصوصية كاملة — هما ما يبني الثقة التي لا يمكن نسخها من منافس.
  4. ما لا يُبنى الآن؟كل ما ورد صراحة في القسم 29 من المواصفات، بالإضافة: لا خريطة مهجر تفاعلية أو خريطة معرفة قبل إثبات ثقة اطمّن ومحرك الملاءمة فعليًا في السوق.
  5. أعلى المكوّنات خطورة؟اطمّن (أمان/خصوصية) ووضع الأزمة التلقائي (خطر False Positive يضرب الثقة التحريرية في حادثة واحدة).
  6. الميزانية الواقعية؟$68,000–$90,000 حتى V2، أو $26,000–$34,000 لـ MVP وحده كمنتج قابل للإطلاق فعليًا.
  7. ما قد يزيد المدة أو الميزانية؟ضعف بيانات كافية لضبط كشف التكرار، تعقيد قانوني متعدد الدول، وزحف نطاق بعد رؤية العميل للديمو الجاهز بصريًا.
ماذا كنت سأغيّر كمهندس أول

نقل بوابة SMS/OTP إلى بند تكلفة تشغيلية إلزامية في MVP. إضافة Pen Test مستقل كبند غير قابل للتفاوض قبل الإطلاق، لا توصية اختيارية. تحديد عتبة «شدّة الحدث» رقميًا منذ التصميم. البدء بلغة عربية واحدة في MVP الفعلي وتأجيل الإنجليزية لمنتصف V1.

ملخص تنفيذي — Executive Project Summary

هذا القسم موجّه للعميل ولأصحاب القرار. التفاصيل الهندسية الدقيقة موجودة في الأقسام اللاحقة.

منصة جسور (Jusoor) هي منصة إخبارية واستخباراتية للمصريين في المهجر، مبنية على Clean Architecture باستخدام .NET 10 / ASP.NET Core على الـ Backend وNext.js على الـ Frontend، مع PostgreSQL كقاعدة بيانات أساسية. المشروع يتقدّم حاليًا ضمن Phase 1 — خط الأخبار ومحرك الملاءمة، وهي المرحلة الثانية من أصل ست مراحل هندسية معرّفة في خطة المشروع.

ما تم إنجازه فعليًا حتى الآن

  • Phase 0 — الأساس التقني: تم تنفيذه بالكامل، وتم تأكيد نجاحه محليًا من قِبل المطوّر (Docker Compose، Backend build/test، EF Core Migrations، Frontend lint/build، وتدفّق Authentication الأساسي). 🟢 COMPLETED & VERIFIED
  • Phase 1 / Slice 1 — Domain persistence لخط الأخبار (Story، Article، RelevanceResult): تم تنفيذه واختباره وتأكيده من قِبل المطوّر على بيئة حقيقية (build، Unit Tests، EF Migration، Integration Tests). 🟢 COMPLETED & VERIFIED

ما تم تنفيذه وينتظر التأكيد النهائي

  • Phase 1 / Slice 2 — SSRF-Safe Fetcher + RSS Ingestion: الكود مكتمل هندسيًا (بما في ذلك الحماية من SSRF وDNS Rebinding وXXE)، لكنه لم يمرّ بعد بدورة build/test فعلية على جهاز المطوّر. 🔵 IMPLEMENTED — AWAITING VERIFICATION

ما لم يبدأ بعد

بقية نطاق Phase 1 (Scheduler، Relevance Engine، Homepage الحقيقية)، وكل من Phase 2 حتى Phase 5 — راجع الأقسام التفصيلية أدناه.

ملاحظة أمانة توثيقية: هذه الوثيقة لا تصف المشروع بأنه "Production Ready" في أي قسم، لأن الأدلة الحالية لا تدعم هذا الوصف. Implementation ≠ Verification، وVerification ≠ Production Readiness، وProduction Readiness ≠ Client Acceptance — وهذه الوثيقة تحافظ على الفصل بين هذه المفاهيم الأربعة بدقة.

Phase 0 — الأساس التقني 🟢 COMPLETED & VERIFIED

Client View

في هذه المرحلة تم بناء الأساس التقني الذي يسمح للمنصة بالعمل بأمان: نظام تسجيل دخول حقيقي، قاعدة بيانات حقيقية، وبيئة تطوير يمكن لأي مطوّر جديد تشغيلها خلال أقل من ساعة.

Engineering View

Clean Architecture skeleton (Domain → Application → Infrastructure → Api)، ASP.NET Identity + JWT Authentication، PostgreSQL عبر EF Core، Docker Compose لبيئة التطوير المحلية، وGitHub Actions CI/CD أساسي.

Detailed Implementation

  • Identity model: ApplicationUser : IdentityUser مع DisplayName، PreferredLanguage
  • User Registration + Login (RegisterCommand، LoginCommand عبر MediatR + FluentValidation)
  • Password Hashing عبر ASP.NET Identity الافتراضي
  • JWT Issuance (JwtTokenService) — بدون أي Signing Key ثابت في الكود، القراءة إلزامية من Configuration
  • Anti-enumeration على Login (رسالة فشل عامة موحّدة لكلمة مرور خاطئة أو مستخدم غير موجود) — مُثبَت باختبار Integration مخصّص
  • 11 Newsroom Roles (من Spec §25) مزروعة (Seeded) كـ Identity Roles — بدون تفعيل RBAC فعلي بعد (مؤجّل لـ Phase 3)
  • Global Exception Handling Middleware — لا Stack Trace يصل للعميل أبدًا
  • Country، City Entities (الطبقتان الأوليان من الهرمية الجغرافية، Region/Neighborhood مؤجّلة لـ Phase 2)
  • Source Entity (7 Source Layers من Spec §5)
  • AuditableEntity SaveChanges Interceptor (تعبئة CreatedAtUtc/LastModifiedAtUtc تلقائيًا لكل Entity قابل للتدقيق)
  • ApplicationDbContextFactory (Design-time factory) لضمان عمل dotnet ef بشكل موثوق دون تنفيذ منطق Program.cs الحيّ

Remaining Phase 1 Scope

حسب WBS الأصلي، Phase 1 يتضمّن أيضًا العناصر التالية التي لم يبدأ تنفيذها بعد:

  • Scheduler (Hangfire أو بديل) لتشغيل Ingestion تلقائيًا — القرار المعماري لم يُتَّخذ بعد
  • Source Workers لطبقات مصادر إضافية غير RSS (طبقات 1، 4، 5، 6، 7 من §5)
  • مراحل Pipeline: Validate (بمعنى Content Validation المتقدّم)، Sanitize، Cross-Source Deduplication، Geographic Extraction
  • Relevance Engine v1 (Rules + Embeddings + LLM للحالات الحدّية) — لم يبدأ
  • AI Gateway / Semantic Kernel Integration — لم يبدأ
  • pgvector Embeddings Column — لم يُضَف عمدًا حتى تُستخدَم فعليًا (تجنّبًا لإضافة أعمدة غير مُستخدَمة)
  • Homepage SSR الحقيقية + Article Page — الواجهة الأمامية ما زالت تعرض صفحة Placeholder فقط
